Mitä 300 marjanpoimijaa opetti minulle ohjelmistoista, joista ei voi kieltäytyä

20. syyskuuta 2026, päivitetty 3. marraskuuta 2026 · 8 min lukuaika

Useimmissa ohjelmistoissa on takaovi. Jos sovellus ärsyttää, suljet välilehden. Jos kassa on hidas, ostat muualta. Rannikon Puutarha on marjatila Halikossa Varsinais-Suomessa, eikä sille rakentamassani ohjelmistossa ole takaovea. Jos tuntilaskentani on väärin, joku yksitoista tuntia mansikkaa poiminut saa palkan yhdeksältä. Hän ei voi vaihtaa kilpailijaan. Hän vain saa vähemmän rahaa.

Järjestelmää käyttää joka kausi yli 300 kausityöntekijää kuudessa asuntoryhmässä ja viidellä kielellä: englanniksi, ukrainaksi, khmeriksi, vietnamiksi ja nepaliksi. Suurin osa heistä tulee Ukrainasta, Kambodžasta, Vietnamista ja Nepalista. Harva heistä lukee koskaan julkaisutiedotetta. Tämä on se, mitä sen rakentaminen opetti.

Ohjelmiston piti hävitä väittely paperille

Ennen kuin kirjoitin riviäkään koodia, Rannikon toimi neljällä paperilomakkeella, ja jokaisessa oli vuosien mittaan neuvotellut säännöt:

  • Valkoinen paperi — tuntipalkkainen työ.
  • Oranssi paperi — lisätyö, enintään 3 tuntia päivässä maanantaista perjantaihin ja 11 tuntia lauantaina.
  • Viikkoyhteenveto — maanantaista sunnuntaihin, enintään 17 lisätuntia viikossa, ja allekirjoitusrivi, jolla työntekijä vahvistaa haluavansa lisätunnit.
  • Vihreä paperi — marjanpoiminta, kirjattuna kiloina eikä tunteina.

Kehittäjän vaistoni oli yksinkertaistaa tämä. Yksi siisti taulukko, yksi summa, valmis. Vaisto oli väärässä. Juuri näitä neljää lomaketta vasten palkanlaskenta tarkistaa työt, ja niitä työsuojelutarkastaja kysyisi. Rajat eivät ole minun käyttöliittymäpäätöksiänä, vaan ehdot, joilla ihmiset tekevät työtä.

Sovellus ei siis korvaa lomakkeita. Se tuottaa ne — samat neljä dokumenttia, sama sarakejärjestys, ladattavissa PDF:nä tai Excelinä, työntekijän nimi ja työnumero yläreunassa.

Yksi laskenta, yhdessä paikassa, ja rumempi kuin haluaisit

Näin Rannikonin työpäivä oikeasti lasketaan. Ensimmäiset 30 minuuttia taukoa ovat palkatonta ruokataukoa. Jos pidit sen tauon, palkallinen päiväsi mitataan 8 tunnin 30 minuutin ikkunassa; jos et, ikkuna on 8 tuntia. Kaikki sen yli menevä lakkaa olemasta valkoisen paperin työtä ja muuttuu oranssin paperin lisätyöksi. Ensimmäisen 30 minuutin yli menevä tauko vähennetään lisätyöstä, ei säännöllisistä tunneista.

Siinä on koko liiketoimintalogiikka. Se on noin viisitoista riviä ja projektin tärkein koodi:

function calculate(actualStart, actualFinish, breakMins) {
  const totalBreak = Math.max(0, breakMins || 0)
  const extraBreak = Math.max(0, totalBreak - 30)

  const workedMins = toMins(actualFinish) - toMins(actualStart)
  const WHITE_WINDOW = totalBreak >= 30 ? 510 : 480

  if (workedMins <= WHITE_WINDOW) {
    // lyhyt päivä: kaikki on valkoista paperia, tauko vähennettynä
    return { white_hours: toHHMM(workedMins - totalBreak), orange_hours: '0:00', ... }
  }

  // pitkä päivä: valkoinen katkeaa 8:00 kohdalla, loput on oranssia
  const orangeStart = addMins(actualStart, WHITE_WINDOW)
  const orangeMins  = toMins(actualFinish) - toMins(orangeStart) - extraBreak
  return { white_hours: '8:00', orange_hours: toHHMM(orangeMins), ... }
}

Julkaisin varhaisen version, jossa käyttöliittymällä oli oma kopionsa tästä, jotta työntekijä näkisi summan kirjoittaessaan. Se erkani. Versiot olivat eri mieltä ylimääräisen tauon säännöstä, ja hetken aikaa ruutu kertoi ihmisille yhden luvun ja palkanlaskenta kirjasi toisen. Kukaan ei huomannut sitä päiväkausiin, mikä on pahin tapa saada se selville.

Nyt tämä funktio on olemassa kerran, Fastify-taustajärjestelmässä, eikä puhelimella saa olla mielipidettä. Työntekijä kirjoittaa alun, lopun ja tauon; palvelin palauttaa jaon. Se maksaa yhden kyselyn. Se kannattaa.

Oikea laite on halpa Android-puhelin yhdellä palkilla

Rakensin tämän kannettavalla, kuituyhteydellä, englanniksi. Yksikään noista oloista ei vallitse siellä, missä sitä käytetään. Työntekijät avaavat sovelluksen pellolla, usein edullisella Android-puhelimella, kielellä joka ei ole englanti, käsillä jotka ovat poimineet aamukuudesta asti.

Se ohjasi monta ratkaisua, jotka näyttävät demossa ylivarovaisilta ja osoittautuvat käytännössä koko tuotteeksi: isot kosketusalueet, valmiit vaihtoehdot vapaan tekstin sijaan, kapealla näytöllä kestävä asettelu ja Expo- ja React Native -mobiiliversio Next.js-verkkosovelluksen rinnalla.

Anna ihmisten tarkistaa työnantajansa laskutoimitus

Tämä on ominaisuus, josta olen iloisin, eikä se ollut alkuperäisessä toimeksiannossa.

Työnjohtajat kirjaavat asuntoryhmänsä tunnit. Työntekijät kirjaavat myös omansa. Suurimman osan kaudesta luvut täsmäävät, ja kun ne eivät täsmää, vanha prosessi oli työntekijän ja työnjohtajan välinen väittely ilman yhteistä todistetta — ja työntekijä hävisi sen lähes aina.

Sovellus näyttää siis molemmat rinnakkain ja laskee erimielisyydet: tarkistetut päivät, täsmäävät, poikkeavat, puuttuvat ja kokonaistunnit. Työntekijä voi ajaa sen itse ennen kuukauden sulkeutumista, keneltäkään lupaa kysymättä.

Luottamusominaisuus on outo asia perustella kustannuslaskelmassa. Se ei nopeuta palkanlaskentaa. Se tekee kuukauden loppusummasta puolustettavan, ja se on varsinainen tuote.

Kaiken hyvän siinä pyysi joku, joka tekee työn

Ensimmäinen versio oli työaikalaskuri eikä mitään muuta. Jokainen aidosti hyödyllinen osa tuli siitä, että joku pyysi:

  • Ryhmäkirjaus, koska 40 työntekijän kirjaaminen yksitellen on huonompi työ kuin paperi, jonka se korvasi.
  • Marjanpoimintalomake kiloina, koska tunnit ovat väärä yksikkö urakkatyölle.
  • PDF- ja Excel-vienti, koska palkanlaskennan jatkoprosessi odottaa tiedostoja, ei kirjautumista.
  • Palkanlaskentaan lähetys muistiinpanokenttäineen ja näkyvine historioineen, koska ”lähetitkö kesäkuun?” oli toistuva puhelu.

Mikään näistä ei syntynyt suunnitteludokumentista. Ne syntyivät istumalla alas Linan, Aleksin ja Johannan kanssa. Jokainen merkittävä päätös eteni huoneessa, ei sähköpostissa — epämukava oppi kehittäjälle, joka mieluummin lähettäisi viestin.

Mihin se päätyi

Työntekijän näkymä nostaa nyt esiin neljä lukua, joilla on hänelle oikeasti merkitystä: kokonaistunnit, säännölliset tunnit, lisätunnit ja poimitut kilot. Ei kaavioita ensin. Luvut ensin, kaavio toisena.

Teknologiat, jos ne kiinnostavat: Next.js 16 ja React 19 verkossa, Fastify 5 ja PostgreSQL taustalla, Expo ja React Native mobiilissa. Kiinnostavat ongelmat eivät juuri liittyneet niihin. Ne olivat 30 minuutin ruokatauko, neljä paperiarkkia ja viisi kieltä.

Ennen Rannikonia työntekijät täyttivät ne neljä lomaketta käsin ja palkanlaskenta käytti päiväkausia niiden tarkistamiseen. Nyt tarkistus vie minuutteja. Koko toteutus — arkkitehtuuri, roolit, ylläpidon puoli ja julkaisu — on kuvattu kunnolla Rannikonin case-esimerkissä.
